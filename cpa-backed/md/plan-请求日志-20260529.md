# Plan: 请求日志

## 用户原始需求

为当前项目添加一个请求日志页面，可以看到每一次请求的时间、使用的模型、输入 token、输出 token、缓存 token 数量、按 OpenAI 官方 API 价格估算的费用、以及请求使用的是哪个授权文件。时间使用北京时间。当前系统只用于中转 OpenAI 请求。

## 技术方案设计

1. 新增管理接口 `GET /v0/management/openai-request-logs`，从现有 request log 文件中提取摘要。
2. 新增内置独立页面 `/request-logs.html`，通过 Management Key 调用管理接口。
3. 复用现有 request log 文件，不引入新的数据库或 Redis 依赖：
   - 读取 `logs` 目录下的请求日志文件。
   - 排除主日志 `main.log`，按文件修改时间倒序返回。
   - 从日志内容解析请求时间、请求 ID、模型、授权信息、HTTP 状态和 usage token。
4. Token 解析优先支持 OpenAI 风格 usage：
   - `usage.prompt_tokens` / `usage.input_tokens`
   - `usage.completion_tokens` / `usage.output_tokens`
   - `usage.prompt_tokens_details.cached_tokens` / `usage.input_tokens_details.cached_tokens`
   - `usage.completion_tokens_details.reasoning_tokens` / `usage.output_tokens_details.reasoning_tokens`
   - Codex Responses 包装格式 `response.usage`
5. 价格估算内置 OpenAI 官方 API 标准价格表，按每 100 万 token 计价：
   - 非缓存输入：`(input - cached) * input_price`
   - 缓存输入：`cached * cached_input_price`
   - 输出：`output * output_price`
   - 未匹配价格的模型返回 `price_available=false`，页面显示未匹配。
6. 时间统一转换为 `Asia/Shanghai` 后返回和展示。

## 风险点

- request log 文件格式是文本日志，不是结构化数据库；解析逻辑需要保持宽容，避免单个异常日志影响整个列表。
- 官方价格会随时间变化；本次内置价格表以 2026-05-29 查询到的 OpenAI 官方 API Pricing 和模型页面为准，后续价格变动需要更新代码。
- 超大日志文件可能包含大量正文；摘要接口只做有限读取，优先保障列表页可用。
