# Plan: 认证文件-批量启停

## 用户原始需求

为当前项目认证文件页面添加批量启用、批量禁用开关。当前禁用或启用账号需要单个操作，需支持勾选多个账号后批量启用或批量禁用。

## 技术方案设计

1. 新增管理接口 `PATCH /v0/management/auth-files/status/batch`。
2. 请求体支持：
   - `names`: 认证文件名或 auth ID 数组
   - `disabled`: `true` 表示批量禁用，`false` 表示批量启用
3. 复用现有单个启停逻辑的状态语义：
   - 禁用：`Disabled=true`、`Status=disabled`、`StatusMessage=disabled via management API`
   - 启用：`Disabled=false`、`Status=active`、清空 `StatusMessage`
4. 返回每个账号的处理结果，部分失败时返回 `207 Multi-Status`，全部成功返回 `200 OK`。
5. 管理页面不是仓库内前端源码，而是运行时下载的 `management.html`；在服务端返回该 HTML 时注入轻量增强脚本：
   - 仅在认证文件路由显示。
   - 调用 `GET /v0/management/auth-files` 渲染账号勾选列表。
   - 调用新增批量接口执行批量启用/禁用。
   - 支持手动输入 Management Key，兼容页面未暴露内部鉴权状态的情况。

## 实施步骤概要

1. 抽取认证文件查找与状态应用 helper。
2. 新增批量状态接口和路由。
3. 补充批量成功、部分失败、参数校验测试。
4. 修改 `serveManagementControlPanel`，在返回 HTML 时注入批量操作脚本。
5. 执行可用校验；如本地缺少 Go 工具链，在 impl 文档记录限制。

## 风险点

- 管理页面 HTML 来自外部构建产物，DOM 结构可能变化；注入脚本应尽量独立渲染，不依赖 React 内部结构。
- 批量接口需要保持单个失败不影响其他账号处理。
- 当前工作区已有其他未提交改动，本任务只修改相关文件。
