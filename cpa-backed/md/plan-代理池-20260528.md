# Plan: 代理池

## 用户原始需求

当前项目只能配置一个 SOCKS5 形式的 IP 代理。由于单个代理 IP 容易被封控，需要支持配置多个代理，每次请求随机从代理池中选择代理 IP 请求上游；同时新增一个单独页面用于配置这些 IP，并能在请求日志中看到本次请求使用了哪个代理 IP。

## 技术方案设计

1. 在 `SDKConfig` 中新增 `proxy-pool` 配置项，元素包含 `name`、`url`、`disabled`。
2. 保持兼容现有 `proxy-url`：
   - auth 级 `proxy-url` 仍最高优先级。
   - 未配置 auth 级代理时，优先从全局 `proxy-pool` 的启用项随机选择。
   - `proxy-pool` 为空时回退到原有全局 `proxy-url`。
3. 在运行时请求上下文中缓存本次客户端请求选中的代理，保证日志和实际 HTTP client 使用同一个代理。
4. 在 upstream request log 的 `API REQUEST` 区块增加 `Proxy: ...` 字段，使用脱敏后的代理 URL。
5. 新增管理 API：
   - `GET /v0/management/proxy-pool`
   - `PUT /v0/management/proxy-pool`
   - `PATCH /v0/management/proxy-pool`
   - `DELETE /v0/management/proxy-pool`
   - `GET /v0/management/proxy-pool/request-logs`
6. 新增内置独立页面 `/proxy-pool.html`，通过 Management Key 调用上述 API，支持代理池配置和最近请求代理使用情况查看。

## 风险点

- 控制面板主页面由外部 release 下载，本仓库无法直接改其前端路由，因此本次用 `/proxy-pool.html` 提供内置独立页面。
- 当前环境缺少 `go` 命令，若无法安装或使用 Go 工具链，本地编译和测试会受限。
- 部分 OAuth/token 刷新路径也会使用代理配置，本次重点覆盖运行时请求上游路径，并尽量复用统一代理选择函数。
