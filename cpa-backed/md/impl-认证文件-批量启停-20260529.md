# Impl: 认证文件-批量启停

## 任务概述

为认证文件管理增加批量启用、批量禁用能力。后端新增批量状态接口，管理面板在认证文件页面注入独立批量操作面板，支持勾选多个账号后一次性启用或禁用。

## 核心代码说明

- 新接口：`PATCH /v0/management/auth-files/status/batch`
  - 请求体：`{"names":["a.json","auth-id"],"disabled":true}`
  - `disabled=true` 表示批量禁用。
  - `disabled=false` 表示批量启用。
  - `names` 支持认证文件名、auth ID、以及 auth path 的 basename。
- 批量处理逐项执行，单个账号失败不会阻断其他账号。
- 全部成功返回 `200 OK`；部分失败返回 `207 Multi-Status`，响应中包含 `failed` 明细。
- 单个启停接口复用相同 helper，避免单个操作与批量操作状态语义不一致。
- 批量与单个启停在更新运行时 authManager 前会显式持久化带 metadata 的认证记录，避免 `authManager.Update()` 吞掉底层保存错误后仍返回成功。
- 管理面板 HTML 注入脚本仅在 `auth-files` 页面显示，独立拉取 `/v0/management/auth-files` 渲染勾选列表并调用批量接口。

## 接口文档

- `PATCH /v0/management/auth-files/status/batch`
  - 认证：同其他 management API，使用 `Authorization: Bearer <key>`。
  - 请求：
    ```json
    {
      "names": ["alpha.json", "beta-auth-id"],
      "disabled": true
    }
    ```
  - 成功响应：
    ```json
    {
      "status": "ok",
      "disabled": true,
      "updated": 2,
      "files": [
        {"name": "alpha.json", "id": "alpha-id", "disabled": true}
      ]
    }
    ```
  - 部分失败响应：HTTP `207`
    ```json
    {
      "status": "partial",
      "disabled": true,
      "updated": 1,
      "files": [],
      "failed": [{"name": "missing.json", "error": "auth file not found"}]
    }
    ```
