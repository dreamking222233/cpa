## 后续同步建议

后续再跟官方同步时，建议固定按以下顺序执行：

1. 主仓库与前端子仓库分别检查状态
2. 各自 stash / 提交本地改动
3. 各自 fetch 最新远端
4. fast-forward 或 rebase 到最新上游
5. 重新应用本地改动
6. 跑后端构建和前端构建

这样可以避免 `.frontend/` 这种子仓库被主仓库的 Git 操作误判或遗漏。
