# Impl: 代理池

## 任务概述

实现全局代理池配置，支持在未配置 auth 级代理时为每个客户端请求随机选择一个代理访问上游，并在请求日志中记录本次上游请求使用的代理。新增独立内置页面 `/proxy-pool.html` 用于配置代理池和查看最近请求代理使用情况。

## 核心代码说明

- 代理优先级保持兼容：`auth.ProxyURL` > `proxy-pool` 随机启用项 > `proxy-url`。
- `ResolveProxyURL` 会把本次请求选中的全局代理缓存到 Gin context，确保日志和实际 HTTP client 使用同一个代理。
- 请求日志的 `=== API REQUEST ... ===` 区块新增 `Proxy: ...` 行，并使用 `proxyutil.Redact` 隐藏账号密码和路径。
- `/v0/management/proxy-pool/request-logs` 从最近 request log 文件中提取全部 `Proxy:` 行，`proxy` 默认返回最后一次上游尝试的代理，`proxies` 返回完整尝试链路。
- `SanitizeProxyPool` 在配置加载阶段会丢弃无效代理 URL，避免日志记录了实际未使用的代理。
- 代理池只接受具体代理 URL，不接受 `direct`/`none`，避免随机直连。
- `/proxy-pool.html` 与现有 `/management.html` 一样尊重 `remote-management.disable-control-panel`。
- OAuth/登录辅助请求、管理页手动 API 调用、版本检查和管理面板资源更新也复用 `EffectiveProxyURL`，避免仍固定走单一 `proxy-url`。

## 接口文档

- `GET /v0/management/proxy-pool`: 返回 `{"proxy-pool":[...]}`
- `PUT /v0/management/proxy-pool`: 使用 `{"value":[...]}` 替换代理池
- `PATCH /v0/management/proxy-pool`: 支持 `add`、`update`、`delete`
- `DELETE /v0/management/proxy-pool`: 清空代理池
- `GET /v0/management/proxy-pool/request-logs?limit=100`: 返回最近请求日志中的代理使用摘要
