# Review: 前端管理中心改造

## 复审结论

本次复审先发现 3 个需要收敛的问题，随后已完成修复并重新验证：

1. 请求日志和代理使用日志接口会把 `error-*.log` 一并纳入统计，导致请求总数和页面列表被脏数据污染。
2. 新增前端页面把核心数据和补充日志数据绑在同一个 `Promise.all` 中，补充日志失败时会拖垮整个页面。
3. 代理池需求约束为 SOCKS5，但前后端最初实现实际接受 `http/https` 代理。

以上 3 项均已修复，当前没有继续阻塞交付的问题。

## 已修复项

### 1. 过滤非请求日志

- 在后端新增统一的请求日志文件名过滤逻辑：
  - 排除 `main.log`
  - 排除 `error-*.log`
- 应用位置：
  - `internal/api/handlers/management/logs.go`
  - `internal/api/handlers/management/proxy_pool.go`
  - `internal/api/handlers/management/request_log_summary.go`
- 新增测试覆盖：
  - `internal/api/handlers/management/proxy_pool_test.go`
  - `internal/api/handlers/management/request_log_summary_test.go`

### 2. 页面降级容错

- `ProxyPoolPage` 改为：
  - 代理池配置是核心数据；
  - 最近代理使用记录是补充数据；
  - 补充数据失败时仅展示 warning，不阻断代理池管理。
- `RequestLogsPage` 改为：
  - OpenAI 请求摘要是核心数据；
  - 代理出口映射是补充数据；
  - 代理日志接口失败时仍展示请求日志和 token 汇总。

### 3. SOCKS5 约束落地

- 后端 `normalizeProxyPoolEntry` 现在只接受：
  - `socks5://`
  - `socks5h://`
- 前端新增和编辑代理时也同步校验，只要不是上述协议就直接提示错误，不再提交到后端。

## 验证结果

- 前端：
  - `npm run type-check` 通过
  - `npm run build` 通过
  - 本地预览 `http://127.0.0.1:4174/` 可访问
- 后端：
  - `go test ./...` 通过
  - `go build -o /tmp/cpa-server ./cmd/server` 通过

## 剩余风险

- 请求日志页中的代理出口仍依赖 `request_id` 关联两份日志数据；如果后端未来调整 request log 文件命名规则，需要同步更新前端或后端的关联方式。
