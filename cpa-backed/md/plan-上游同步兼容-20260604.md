# 上游同步兼容 Plan

## 用户原始需求

将当前本地 CPA 更新到官方 GitHub 最新版本，同时保留并兼容本地已有修改。

## 当前状态

- 当前本地分支：`main`
- 当前本地提交：`fd3094483084ae0c6913e56258d2baa5ba85223b`
- 官方最新拉取结果：
  - `upstream/main` 已更新到 `5753d1a0`
  - 新标签：`v7.1.45`
- 当前工作区存在大量已修改和未跟踪文件，不能直接 `pull --rebase` 或硬覆盖

## 技术方案设计

### 目标

1. 更新本地基础代码到官方最新版本
2. 保留当前未提交的本地功能改动
3. 在冲突点做兼容处理，保证当前功能不被上游覆盖
4. 完成后验证后端构建/测试与前端构建

### 方案

1. 使用 `git stash -u` 对当前工作区做完整快照
2. 将本地 `main` 快进到 `upstream/main`
3. 重新应用 stash
4. 逐个解决冲突，优先保留本地定制功能，同时适配上游最新代码
5. 运行关键测试与构建验证

### 风险点

1. 上游最新版本可能修改了相同文件，stash apply 后出现冲突
2. 前端项目位于 `.frontend/` 且为未跟踪目录，需要一并保留
3. 当前代理池、请求日志、图片接口限制等定制逻辑涉及多个核心模块，冲突概率较高

## 涉及文件范围

- Git 工作区整体
- 重点关注：
  - `internal/api/`
  - `internal/config/`
  - `internal/runtime/executor/`
  - `sdk/api/handlers/openai/`
  - `.frontend/Cli-Proxy-API-Management-Center/`

## 实施步骤概要

1. 记录当前本地状态并创建同步方案
2. stash 当前改动（含未跟踪文件）
3. fast-forward 到 `upstream/main` / `v7.1.45`
4. 重新应用本地改动并处理冲突
5. 运行 Go 测试、Go 构建、前端构建
6. 输出实施记录与后续同步建议
